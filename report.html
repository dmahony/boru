4. How version changes are calculated

scripts/version.py inspects conventional commits between the commit stored in .version-state.json and HEAD. It classifies each commit:

  • fix, perf, refactor, revert to patch level
  • feat to minor level
  • ! or BREAKING CHANGE: to breaking level
  • docs, style, test, ci, chore, build to no bump

The highest-impact change wins (breaking > feature > fix > none).

For versions below 1.0.0: breaking to minor. For 1.0.0+: breaking to major.

5. How the commit range is tracked

.version-state.json stores the current version and the full SHA:

{"version": "0.101.0", "commit": "e3d8435edab8ce527d62db70f551fa44c17fd652"}

Each run inspects commits after this stored commit.
