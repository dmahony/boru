## What was implemented (plan step by step)

1. **Horizontal page padding 28-32 px** — 32 px at large widths (`is_large`, ≥ 1440), 28 px elsewhere
   (`app.rs:25167-25171`). The old 3-band 32/24/16 rule is replaced by a 2-band rule, which also
   removes the `is_medium` band gap noted in the UI-HOME-01 audit (§5, §10).
2. **Top padding 28 px below the application header** — `iced::Padding::from([SPACE_28, h_padding]).bottom(SPACE_32)` (`app.rs:25188`).
3. **Bottom padding ≥ 32 px** — `.bottom(SPACE_32)` (same line).
4. **Max content width 1440-1520 px, centred** — `DASHBOARD_MAX_WIDTH = 1480.0`
   (`design_tokens.rs:222-225`), applied as `.max_width(...)` on the inner container; the outer
   canvas is `.align_x(Alignment::Center)` (`app.rs:25186-25195`). Only binds on very wide windows
   (e.g. 1920), keeping the grid from stretching edge-to-edge.
5. **Vertical page scrolling** — the whole canvas stays wrapped in
   `crate::ui_components::gutter_scrollable` (`app.rs:25197-25200`); no fixed page height added.
6. **Desktop grid** — `FillPortion(2)` / `FillPortion(1)` → 66.7% / 33.3% (plan band 65-68% /
   32-35%); 24 px column gap (`SPACE_24`, `app.rs:25138`); 20 px vertical card gaps (`card_gap =
   SPACE_20`, plan band 20-24 px; used for hero→mesh→actions and rail cards); both columns
   top-aligned (`align_y(Alignment::Start)` on the row, `app.rs:25141`).
7. **Header** — greeting + subtitle left, compact status pill right (`app.rs:25094-25105`).
   - Greeting 32 px (`HOME_GREETING`, plan band 30-34 px) — was 28 px `PAGE_TITLE`.
   - Subtitle 16 px (`HOME_SUBTITLE`, plan band 15-17 px) — was 15 px `TYPO_SM`.
   - Status pill ~36 px tall: padding `[SPACE_10, SPACE_12]` (10 px vertical) over 16 px content
     (plan band 36-40 px) — was 6 px vertical padding.
8. **Column collapse at narrower widths** — `RAIL_STACK_BREAKPOINT = 1120.0` (`app.rs:25112`);
   below it the right rail stacks below the left column (`app.rs:25125-25133`) instead of
   compressing cards. Raised from the old 900 px so the medium band collapses cleanly. Full
   responsive pass (breakpoints tuning, per-card reflow) is deferred to UI-HOME-15 per scope.

## Remaining risks / notes

- Quick-action card clipping at 1280×800 (4-column grid, fixed 132 px height) is **pre-existing**
  and explicitly out of scope; unchanged by this card. UI-HOME-06 fixes it.

  responsive pass and may tune it.

  three supported widths content fills the region, so no visual change there.

  before this task; the file compiles and tests fine). Not addressed here to avoid scope creep.
