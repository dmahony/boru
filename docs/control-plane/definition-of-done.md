## Cross-cutting engineering requirements — verification

| Requirement | Evidence | Verdict |
|---|---|---|
| No control-plane/chat coupling: discovery handlers never call normal chat rendering/history paths | DiscoveryService owns its own gossip subscription and drain; the receive path returns `IncomingOutcome`/`ControlEvent` and never creates conversations/peer updates (`discovery_service.rs:1029-1328`); BORU-DISC-13 layer map shows every chat surface (history, message DB, attachments, notifications, typing, read receipts, rendering, unread, room metadata, backfill) is blocked from discovery traffic with at least one guard (`docs/discovery-refactor/13-persistence-isolation.md:30-44`); integration proof: `extensions_envelope_never_touches_peer_registry`, `conversation_forwarder_drops_discovery_topic_events`, `valid_and_malformed_discovery_traffic_produces_no_ui_state` | **PASS** |
| No authorisation by presence: discoverable ≠ friend/group member/tunnel client/file recipient | `PeerControlStateStore` is a metadata cache with no authorisation surface (`privacy.rs:37-43`); app owns the friendship gate — only `can_message()` friends get reconnect attempts (`main.rs:1301-1310`); reconcile returns nothing for non-friends/blocked/archived (`reconcile.rs:17-24, 71-90`); capability advertisements never grant access (`capabilities.rs:171-177`); tests: `blocked_peer_not_resurrected`, `non_friend_yields_nothing`, `blocked_friend_yields_nothing_even_with_stale_records`, `extensions_advertisement_never_authorises`, `capabilities_advertisement_never_authorises` | **PASS** |
| Bounded resources: cap peer-cache size, rate-limit announcements, deduplicate, expire stale entries | `MAX_CONTROL_PEERS=1024` + stale-then-oldest eviction (`privacy.rs:79`); `MAX_CONNECTIVITY_PEERS=1024` (`connectivity.rs:152-154`); per-sender rate limit 60 frames/10s window (`privacy.rs:93-96`), `MAX_RATE_LIMITED_SENDERS=4096`; dedup by `(sender, sequence)` with bounded set `CONTROL_DEDUP_CAP=4096` (`privacy.rs:108, 21-23`); `MAX_RECONNECT_PEERS=256` (`reconnect.rs:67`); payload cap `MAX_CONTROL_PAYLOAD_LEN=4096` (`message.rs:89`); TTL expiry sweep (`privacy.rs:104`); tests: `duplicate_presence_flood_bounded` (200 duplicate envelopes → exactly one entry in registry/control/connectivity), `store_is_bounded`, `trail_is_bounded_per_peer`, `scheduler_is_bounded`, `handle_incoming_control_rate_limited_sender_rejected` | **PASS** |
| Backward compatibility: unknown capability/message versions fail closed for that feature but do not break the entire client | Unknown message types → `UnknownType` (header parsed, payload skipped by length prefix) (`message.rs:477-486`); unsupported protocol version → `UnsupportedVersion` (feature dropped, client keeps running) (`message.rs:449-458`); unknown payload fields discarded via `take_from_bytes` trailing-bytes (`message.rs:488-494`); unknown capabilities preserved losslessly (`capabilities.rs:15-19`); tests: `unknown_message_type_is_ignored_safely`, `handle_incoming_unknown_version_*`, `test_unknown_capabilities_are_ignored_not_fatal`, integration `mixed_version_old_client_still_chats` | **PASS** |
| Observability: log state transitions, not message contents | Control-plane logging logs outcomes/transitions: "discovery hello announced on join", "control: presence refresh announced", "connectivity: peer state transition from=… to=… event=…" (`connectivity.rs:157-158`), `control_announce` outcomes (`discovery_service.rs:3340-3357`); the decoder never logs payload contents; `DiagnosticHintPayload` docs: "never carries chat contents, secrets, or message data" (`message.rs:213-214`); `PeerDiagnosticsSnapshot` is share-safe by construction (`diagnostics.rs:18-24`) | **PASS** |
| Deterministic topic ownership: one subsystem owns each topic subscription | DiscoveryService owns the internal discovery topic (only service subscribes; `main.rs:1145`); the app/data plane owns direct/group/public conversation topics; reconcile only *reports* required direct topics — never subscribes itself (`reconcile.rs:31-35`); direct-topic state is a hint recorded from data-plane reports (`connectivity.rs:162-164`); BORU-DISC-10 routing guard classifies topics before deserialisation (`discovery_topic.rs:90-124`) | **PASS** |
| Idempotence: duplicate discovery announcements must not create duplicate connections, conversations, or background tasks | Dedup by `(sender, sequence)` at the receive core (`privacy.rs:21-23`); connectivity state machine is idempotent (duplicate events are no-ops, never re-enter `Connecting`, never spawn a second dial) (`connectivity.rs:94-108`); reconnect scheduler dedups one active attempt per peer (`reconnect.rs:23-27`, tests `schedule_deduplicates_per_peer`, `due_marks_in_flight_and_deduplicates`); reconcile topics deduplicated into `BTreeSet` (`reconcile.rs:29-32`); announce throttles make unchanged re-announcements no-ops (`announce_capabilities_dedups_unchanged_set`); startup-burst scheduler caps concurrent starts (`tests/test_restart_storm_prevention.rs`); tests: `duplicate_presence_flood_bounded`, `handle_incoming_duplicate_event_id_ignored`, `handle_incoming_control_duplicate_sequence_ignored`, `connectivity_loop_deduplicates_peer_dials` | **PASS** |
| Feature flags: land incrementally and keep new behaviours switchable during testing | The whole control plane is behind `#[cfg(feature = "net")]` where network-dependent (`control_plane/mod.rs:44-54`); the UI presence indicator is a Settings toggle (`show_presence_indicator`, `src/bin/boru/app/settings.rs:135, 983-1020`) — disabling it only hides the badge, networking is unaffected (BORU-CP-05/06 design: "presence can be removed from the UI without breaking discovery/reconnection"); the BORU-CP chain landed in 17 small per-task commits, each with its own tests | **PASS** |
